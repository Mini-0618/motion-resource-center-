## 三、深拆

### 3.1 Rea-Video × 自家 video_distill（V1.2 规格）正面对比

**它的拆解粒度**：逐镜（shot）为基本单位，每镜给三件事——①来源判定（实拍／AI 生成／3D／代码／录屏／混合，混合片逐镜分别判再按原时间线重拼）；②证据与复刻路线（实拍给机位、灯光方案与器材清单；AI 片给逐镜反推提示词＋建议模型与生成批次划分；代码片给文字、版式、动效时序，可直接重建为 Remotion 工程）；③时间线外的独立轨：字幕逐句起止（导出 SRT／ASS，含颜色、描边、入场方式）、贴纸与画中画位置时长、剪辑点与卡点、音频轨（人声／AI 声、音乐来源与 BPM、音效落点）、「你需要自己备的素材」清单。输出双份：给人看的 report.html／PDF＋给 agent 按层读取的 VIDEO.md（分层格式，agent 按问题只读需要的层，省 token）。可选接视频理解模型（Gemini／豆包）提高判定精度，不接也能跑（agent 自己看帧复核不确定镜）。

**谁强谁弱（逐项）**：

| 维度 | Rea-Video | V1.2（自家） | 判 |
|---|---|---|---|
| 来源判定（拍／AI／代码） | 核心能力，逐镜判定＋证据，V1.2 没有这一项 | 只记「可观察的素材类型」，不做来源裁决 | **Rea 强，补缺** |
| 逐镜反推提示词 | AI 片每镜一份反推提示词＋模型建议 | 无 | **Rea 强，补缺** |
| 复刻计划 | 按所选模型出 remake 计划，拆到生成批次 | 有制作配方与复现路线，但不按目标模型分批次 | Rea 略强 |
| 输出格式 | VIDEO.md 分层格式，agent 按需读取省 token | 七份文件全量交付，读哪份靠人指 | **Rea 强，格式可借** |
| 时间精度 | 剪辑点与运动时序（README 口径，未见 0.01s 规格承诺） | HH:MM:SS.xx 硬规格＋左闭右开区间＋三层时间轴 | V1.2 强 |
| 方法提炼纪律 | 拆解止于「怎么复刻这条」，无入选门、无六问、无淘汰清单 | 四道入选门＋六问＋每片 ≤12 条＋淘汰清单留痕 | **V1.2 强，不可替代** |
| 置信度与验收 | 有「不确定镜 agent 复核」机制，无标定表、无验收冻结 | 置信度三档标定锚点＋验收标准动手前冻结＋变更降级规则 | **V1.2 强** |
| 知识沉淀 | 单片报告完结，无跨片知识库、无同类合并／降级／废弃 | 五类库＋稳定 ID＋合并降级废弃规则 | **V1.2 强** |
| 音频拆解 | 声源判定、BPM、音效落点成轨 | 音文事件轴覆盖，但无 BPM／声源判定 | Rea 略强 |

**结论**：不是替换关系。V1.2 是「蒸馏成可调用知识」的规格，Rea-Video 是「拆解＋复刻计划」的执行工具，二者缺口正好互补：V1.2 缺的来源判定、逐镜反推提示词、VIDEO.md 分层输出，Rea 都有；Rea 缺的方法纪律、置信度、验收冻结、五类库沉淀，V1.2 都有。**处置：学它的方法层三件——①在 V1.2 逐镜表加「来源判定＋证据」字段；②AI 片逐镜补反推提示词；③七份交付之外加一份 VIDEO.md 式分层索引供 agent 按需读。工具本体是否引入，另行验证（其判定精度依赖可选的视频理解模型 API，未接模型时的准确率 README 只给了个案数字，不当结论）。**

### 3.2 HyperFrames × lemo-opuscar 正面对比

| 维度 | HyperFrames | lemo-opuscar（现役） |
|---|---|---|
| 渲染路线 | HTML 页面＋无头 Chrome 逐帧 seek＋FFmpeg 编码，确定性输出 | 自有渲染入口 `core/render/video.mjs`（Node），风格系统驱动 |
| 创作模型 | 裸 HTML／CSS＋data 属性时间轨道；动画适配器开放（GSAP、CSS、Lottie、Three.js、Anime.js、WAAPI 均可） | 99 种电影风格的 STYLE.md 风格系统，风格即约束 |
| agent 可控性 | 官方 skills 全套（规划→写 HTML→接动画→lint→预览→渲染），多家 agent 通用；另有中文社区 fork 专做中文快节奏短视频 | 靠自家任务书与 lemo 技能驱动，已在三条在产片上跑通 |
| 版式自由度 | 任意 HTML/CSS，版式无上限 | 受风格系统约束，风格内稳定、风格外要改引擎 |
| 生态 | HeyGen 官方维护、目录组件库（blocks）、Studio 桌面端 | 上游 19k star，风格资产是独有存量 |
| 与定版关系 | 裸 HTML 无风格纪律，产出质量全靠写 HTML 的人（agent）自律 | 99 风格已按定版筛过一轮（对照评估：补缺 19／冲突 26 已剔） |

**结论**：比不出换引擎的增量。HyperFrames 的增量在「任意版式自由度＋skills 生态」，代价是丢掉 99 风格系统这份已筛过的存量、且全部在产管线要重搭；用户既有定论「引擎不换」继续成立。**处置：参考级——留索引；它的数据图表等 catalog blocks 的版式思路、以及「seekable 动画适配器」这一抽象，可在 lemo 侧遇到版式瓶颈时点名借鉴，不整仓引入。**

### 3.3 Blender MCP × 天安门 Blender 建模线

**它是什么**：Blender 内装一个插件起 socket 服务，本机跑一个 Python MCP 服务（PyPI 包 `mcp-for-blender`），LLM 经 MCP 工具调用把指令送进 Blender 执行 bpy——建模、改场景、材质、灯光、渲染都可由 agent 直接下手。35k star、MIT、2026-11-18 仍在推送，维护活跃；已从 `blender-mcp` 改名 `mcp-for-blender`，旧配置兼容。

**能不能接上**：能，但有一个硬前提——**它只能操控装有 Blender 的那台机器**。用户已授权的 Blender 线（天安门 3D 建模）在用户本机（RTX 4060）由 Codex 执行；Muse 的 VM 里没有用户的 Blender 工程。所以接入点不在 Muse 的 VM，而在用户本机：由本机的 agent（Codex 或本机 Claude）挂这个 MCP 操控本机 Blender。Muse 侧能做的是出建模规格单（现行分工不变）＋验收渲染图。

**风险（必须写清）**：
1. **任意代码执行面**：MCP 工具本质是把 bpy Python 送进 Blender 执行，等于给 agent 本机代码执行权；只许在本机受控环境装，不许暴露端口到局域网外。
2. **版本兼容**：插件与 Blender 版本、MCP 服务与 PyPI 包版本要对齐，升级 Blender 前先验桥。
3. **产出不可复现性**：agent 交互式建模的步骤不天然留痕，须要求每步导出脚本或存工程版本，否则验收只能看渲染图、无法复现——与用户「参数留记录才算资产」的规矩冲突，接入时要把「每轮存 .blend 版本＋导出操作脚本」写进任务书。

**最小验证方案**：在用户本机装桥（不动 Muse VM）→ 用一个小任务验通（如按规格单生成天安门城楼基座的灰模）→ Muse 按渲染图验收 → 通了再写进 Blender 线任务书。

## 四、分类处置与结论清单

**分类计数（7 个）**：补缺候选 2｜参考／只留索引 3｜现役已覆盖 1｜明确不用 1。

### 建议学的（2）
| 项 | 学什么 | 一句理由 |
|---|---|---|
| Rea-Video（方法层） | 来源判定字段、AI 片逐镜反推提示词、VIDEO.md 分层输出格式 | 正好补 V1.2 蒸馏规格缺的三件，方法纪律仍以 V1.2 为准 |

### 只留索引的（3）
| 项 | 一句理由 |
|---|---|
| HyperFrames | 与 lemo 正面比无换引擎增量，版式思路与适配器抽象遇瓶颈时点名借 |
| EffectCraft | 免费 AE 式桌面合成器（308 效果、MIT/Apache），是给人用的 GUI 工具、与代码管线异构；人工精修动效时可作备选，附带 MCP/CLI 口但不进自动管线 |
| ComfyUI | 出图基建不是视频工具：用户本机 RTX 4060 可跑、Muse 的 VM 跑不动，GPL-3.0 还要留意；等出现明确的本地出图需求再议，不先占管线 |

### 现役已覆盖（1）
| 项 | 一句理由 |
|---|---|
| GSAP | 它是底层动效库而非生产线工具——lemo、HyperFrames 一类引擎都在它这一层之上；其缓动/时间线能力与现役动效层高度重叠，不单独成线。附带一条已核实情报：2025 年起 GSAP 全部插件免费商用（Webflow 收购后），以后任何用到 GSAP 的地方不用再考虑付费插件问题 |

### 明确不用的（1）
| 项 | 一句理由 |
|---|---|
| PixelFX | 264 个实测效果全是游戏向像素粒子（火焰、爆炸、投射物、奥术），像素风与「电影级知识叙事」定版正面冲突，进片即破风格；数量也不是帖子说的 244 |
