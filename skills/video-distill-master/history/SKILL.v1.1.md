# AI 视频蒸馏与制作知识库 · 总控指令 V1.1

## 一、任务与输入

你负责分析参考视频，提取有证据、可迁移的创作方法，并将这些方法整理成其他 AI 可以检索、调用和验证的制作知识。

支持实拍、访谈、剧情、纪录片、广告、教程、录屏、游戏、二维动画、三维渲染、AI 生成视频、代码动效和混合视频。同一条视频可以包含多种形式。**即使无法判断画面是怎样制作的，也要继续分析能够观察到的内容、文案、镜头、声音和剪辑。**

开始前记录以下输入：

- **参考视频**：原文件、可访问位置、视频 ID 和版本。能读取原文件时，记录文件哈希。
- **分析目的**：理解单条视频、提取特定手法、对比多条视频，或为新选题制作样片。
- **用户关注点**：内容结构、文案、视觉、动效、声音、剪辑、工作流，可多选。未指定时执行完整分析。
- **可用材料**：字幕、原稿、分轨音频、工程文件、素材清单和授权说明。有则使用，并注明来源。
- **执行范围**：只分析、提炼制作配方，或实际制作并验证样片。用户只要求分析时，交付到分析和配方即可。

若只有截图、片段、转写稿或视频链接，先说明实际读到了什么，再完成材料足以支持的部分。所有时长、帧号、台词、工具运行结果及验收状态，都必须来自本次可核对的证据。

## 二、证据与状态

**分析结论的证据状态**和**制作配方的执行状态**分别记录。一条方法可以同时是“效果已观察、原理已推断、替代实现已验证”。

| 状态 | 使用条件 |
| --- | --- |
| **已观察** | 在视频帧、音频、字幕、元数据或用户提供的工程中找到了直接证据。注明文件、轨道、时间区间或帧号 |
| **已推断** | 根据观察解释叙事意图、制作原理、相机运动或可能的工作流。写明依据，必要时列出其他合理解释 |
| **已实现** | 已实际执行配方，生成了可以检查的工程、音频、图片或视频。记录产物位置和运行条件 |
| **已验证** | 已按预先声明的验收标准检查实际产物。记录测试输入、比较方法、结果和局限 |

字段还可标记为 **未知、待复核、不适用**。例如，无旁白视频的“配音语速”是不适用；有人声但听不清是待复核；原作者使用的插件缺乏证据时是未知。置信度注明判定依据，工具未提供可靠概率时使用高、中、低。

## 三、第一阶段：建立统一时间轴

1. 使用 FFprobe 读取视频和音频流，记录时长、分辨率、旋转信息、帧率信息、音轨、采样率和声道。对可变帧率素材保留实际显示时间戳 PTS。
2. **可读时间码统一使用 `HH:MM:SS.xx`**，显示到百分之一秒。底层同时保留原始时间戳、时间基和可确认的帧号。画面边界按实际帧定位，音频事件按音频时间定位。
3. 建立三层时间轴：
   - **内容段落轴**记录问题、观点、论据、行动、转折、情绪和结尾。
   - **镜头轴**记录连续镜头及镜头内部的重要变化。
   - **声音与文字事件轴**记录台词、屏幕文字、音乐、音效、停顿和静音。
4. 镜头切分采用左闭右开区间 `[起点, 终点)`。同一画面轨上的镜头连续覆盖分析区间。叠化、擦除、声音提前进入、字幕跨镜等现象作为独立事件记录，允许跨镜和重叠。
5. 提取句级转写。工具支持可靠词级对齐时，再输出词级时间戳。标注听不清、多人重叠、专有名词和低置信度片段。分别保存**实际听到的台词、画面中显示的文字和分析者的概括**。
6. 自动切镜后复核闪白、快速运动、录屏页面切换、画中画与渐变转场。对长镜头内部的动作、焦点或信息变化添加事件标记。

## 四、第二阶段：完成十项蒸馏

| 模块 | 必须回答的问题 | 最终产物 |
| --- | --- | --- |
| **01 内容研究** | 视频面向谁？提出什么问题、观点或戏剧冲突？用了什么例子和证据？结尾兑现了开头的什么承诺？ | 内容分析报告 |
| **02 文案拆解** | 开头怎样引起兴趣？信息按什么顺序释放？句长、语气、重音、情绪和信息密度如何变化？ | 文案方法卡 |
| **03 逐镜拆解** | 每一镜能看到、听到什么？观众的注意力怎样移动？这一镜承担哪项叙事功能？ | 逐镜时间轴 |
| **04 视觉设计** | 主体、背景和包装层分别使用怎样的构图、色彩、明暗、字体气质与图形层级？ | 视觉规范 |
| **05 动效逆向** | 哪个元素在动？位置、大小、透明度、形状或遮罩怎样变化？多个元素如何配合？ | 动效配方 |
| **06 剪辑分析** | 何时切、为何可能在这里切？快慢怎样交替？哪里通过停留、反应镜头、动作衔接或声音跨镜推进内容？ | 剪辑规则 |
| **07 音频研究** | 配音、停顿、音乐、环境声和音效各自在什么时刻发挥作用？哪些声音领先或滞后于画面？ | 声音设计方法 |
| **08 技术复现** | 哪些元素适合代码、实拍、AI 生成、二维动画、三维渲染或后期合成？各路线需要什么输入与人工判断？ | 制作配方、工程或验证样片 |
| **09 工作流提炼** | 换一个选题时，研究、脚本、分镜、素材、制作、剪辑、混音和验收该怎样衔接？ | AI 执行工作流 |
| **10 知识沉淀** | 哪些方法可以独立调用？适用条件、反例和验证记录是什么？已有知识库中是否存在同类方法？ | 可检索的知识条目 |

分析开头时覆盖前 20 秒，短于 20 秒则覆盖全片。同时找出**开头承诺真正兑现的时刻**，即使它出现在更晚的位置。视频没有口播时，分析画面、动作、声音或屏幕文字怎样承担钩子和叙事功能。

内容研究中，分别写明**视频提出的主张、片中展示的证据、已独立核实的事实**。只有实际完成外部核查，才能填写第三项。

## 五、第三阶段：逐镜输出

每个镜头至少记录：

- **定位**：镜头 ID、所属段落、起止时间码、持续时长、首帧和结束边界。
- **画面**：主体、景别、构图、视线焦点、前中后景及镜内变化。
- **动作**：主体运动、相机或画面运动、图形动效、关键姿态与关键时刻。
- **声音与文字**：关联台词、画面字幕、其他可读文字、背景音乐、环境声和音效事件。
- **剪辑**：进入方式、离开方式、与相邻镜头的动作、视线、声音或信息关系。
- **叙事作用**：建立背景、提出问题、给证据、解释、制造悬念、产生情绪、完成转折或收束。
- **制作判断**：可观察的素材类型、已知来源、候选制作方法、实现难度及其原因。
- **证据**：对应时间区间、帧或音频片段、置信度、待人工复核项。

按镜头内容补充专属观察。实拍看机位、表演、光影和动作衔接；AI 画面看主体连续性、起止姿态和场景稳定性；3D 看相对视角、轮廓、高光和材质表现；录屏看操作、焦点引导和结果展示；代码动效看组件、布局、属性变化和时序。混合镜头按图层分别描述。

**素材类型、素材来源、制作软件和授权是四个独立字段。** 可以确认画面表现为三维产品旋转，同时将原始工程、具体软件和授权状态记为未知。

## 六、第四阶段：把观察提炼成可调用的方法

每条有价值的方法都回答六个问题：

1. **看到了什么？** 给出具体镜头和时间码。
2. **它可能起什么作用？** 说明对理解、注意力、节奏或情绪的影响，并标记推断。
3. **它适用在哪里？** 标清是单镜头设计、某类镜头规律，还是跨全片重复的规则。
4. **换了题材要保留什么？** 写出必要条件、可替换变量和常见失效情形。
5. **怎样重做？** 给出可执行步骤、候选工具、时间参数、所需素材和人工判断点。
6. **怎样知道做对了？** 给出能实际观察或测量的验收条件。

例如，一条方法可以写成：“先展示两个条件相近却结果不同的样本，再用一个细节特写引出待解释的变量。”记录原镜头之后，再给一个不同题材的原创例子，并指出它依赖“两个样本具有可比性”。这样其他 AI 才能判断何时调用它。

## 七、第五阶段：技术复现与验证

对入选的视觉、声音或剪辑手法，形成独立配方，包含效果目标、输入素材、授权要求、实现步骤、参数、关键帧或音频事件、工具版本、运行命令和验收标准。可同时保留 FFmpeg、Blender、代码渲染、AI 生成、实拍等不同路线，并说明选择依据。

按执行范围交付：

- **分析任务**交付证据、方法和候选复现路线。
- **实现任务**用自有或获授权素材生成工程与预览，记录实际执行结果。
- **迁移验证任务**更换主体、选题、台词或数据，预先声明要保留哪些风格和叙事关系，再制作样片验证。

同内容重渲可以比较画面、声音和时序误差。换题材时，重点比较构图关系、动作时序、信息释放顺序、节奏和音画落点。不同文件哈希用于识别文件版本。迁移成功需要对应的内容变化和方法验证证据。

仅当明确需要复刻代码动效风格时，才调用 code-video-style-distill skill 作为专项实现与验证工具；自 2026-11-24 起它不属于默认创作流程。

## 八、第六阶段：归档与交付

每条视频交付以下七份文件。缺少输入或证据的部分，在相应文件中注明原因。

| 文件 | 内容 |
| --- | --- |
| `video-analysis.md` | 视频信息、内容结构、核心观点或故事推进、文案技巧、视听规律、结尾设计和可迁移方法 |
| `shots.csv` | 连续镜头区间、画面内容、镜内事件、叙事作用、关联声音与文字事件 ID、证据及置信度 |
| `audio-timeline.csv` | 分轨或分事件的台词、停顿、音乐、环境声、音效、时间戳及关联镜头 |
| `effects.json` | 视觉与动效配方、关键参数、候选实现、证据、状态及已生成的预览或工程路径 |
| `workflow.md` | 换选题后的制作步骤、每步输入输出、自动化范围、人工判断点和调用方式 |
| `assets-manifest.csv` | 素材 ID、类型、已知来源、权利人或许可信息、授权依据、允许用途和未知项 |
| `verification.md` | 本次实际检查的项目、通过项、失败项、待复核项、适用项覆盖情况及迁移测试结果 |

跨视频知识归入五类库：**叙事与文案、镜头与剪辑、动效与视觉、声音与音画同步、AI 制作工作流**。每条知识保留稳定 ID、版本、来源视频、证据时间码、适用场景、输入输出、调用示例和验证记录。合并同类方法时保留全部来源、不同实现和失败案例。

**最终汇报必须让读者一眼看清三件事：从原片观察到了什么，换选题时具体怎么用，哪些做法已经在新作品里验证过。**
